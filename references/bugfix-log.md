# bugfix-log — 真实 bug 清单（症状 → 根因 → 修法 → 谁抓到的）

改 `scripts/midi2mml.py` 前先看这里。每条都是本项目实际踩过、并被 `tests/verify.py` 抓住的。

## 1. 长时值被截断（298 拍只生成 192 拍）

- **症状**：某声部开头是几百拍的长休止，生成的 `r1.` 只有 32 个（192 拍），该声部整体时间轴提前。
- **根因**：`duration_tokens()` 的循环 `while ... and guard < 32` —— guard 上限**写死 32**。
- **修法**：上限改为随 `beats` 增长，且结束后断言 `rest` 归零（不为 0 说明没生成够）。
- **谁抓到**：`tests/verify.py` 报 `音符不符 got=(192.0,...) exp=(298.5,...)`。
- **通用教训**：**任何"按单位长度递归拆解"的循环，上限不能写死常数**；要用 `while rest > eps and guard < f(beats)`，并校验余数。

## 2. 三连音时值算错（1/3 拍 → 0.375 拍）

- **症状**：三连音曲目时值整体偏移。
- **根因**：分母表只给了 2 的幂 `1,2,4,8,16,32,64`，1/3 拍只能用 `1/4 + 1/64 + ...` 凑。
- **修法**：分母表扩到 `1,2,3,4,6,8,12,16,24,32,48,64`，1/3 拍 = `c12`。
- **谁抓到**：`tests/verify.py` 在 `test_edge.mid` 报时值不符。
- **通用教训**：**分母表要覆盖"音乐上可能出现的最小公分母"**，不只是 2 的幂。

## 3. 生成非法八度 `o-1` / `o9`

- **症状**：超低/超高音的 MIDI 生成 `o-1`、`o9`，播放器不认。
- **根因**：MML 只有 `o0`~`o8`（MIDI 12~119），代码没做范围钳制。
- **修法**：`fit_mml_range()` 按八度折回 `[12,119]` 并写 warning。
- **谁抓到**：`make_stress.py` 的 `extremes` 轨（pitch 5 / 127）。

## 4. 整轨差一个八度（音高公式）

- **症状**：校验器报 `got=(...,48) exp=(...,60)` —— 差值恒为 12，**时值与起点全对**。
- **根因**：解析侧写成 `pitch = oct*12 + semi`，但 MML 的 `o4` = MIDI 60，正确是 `pitch = (oct+1)*12 + semi`。
- **修法**：两侧统一为 `(oct+1)*12 + semi`。
- **谁抓到**：`tests/verify.py`。
- **通用教训**：**MML 八度编号与 MIDI 音高差 1**（`o0` ↔ MIDI 12）。凡"生成器"和"解析器"两套实现必须逐项对齐公式，且要有独立校验器兜底。

## 5. 解析器正则吃掉时值数字

- **症状**：`无法解析的字符 'c' 于 'c8d8e8g8'` —— 第一个音就失败。
- **根因**：`NOTE_RE.match(body[i:i+2])` 匹配 `"c8"`，但 `8` 不是合法升降号 → 不匹配 → 落到报错分支。
- **修法**：改为 `re.match(r"([a-g])([\-+]?)", body[i:])`，只吃音名+可选升降号，数字交给 `read_len`。
- **通用教训**：**字符解析要"只消费属于自己的字符"**，时值数字属于下一个 token。

## 6. 变速不同步（多文件会跑偏）

- **症状**：`变速不同步 期望 [(14.25,134),(14.5,133),(14.75,132)...] 实际 [(14.25,134),(14.5,133),(15.5,132),(15.5,131)...]`
- **根因**：初版只在**音符边界**输出 `t`，落在音符内部/休止中部的变速点被推迟到下一个边界，多个变速点挤在同一位置。
- **修法**：`voice_to_mml()` 重写 —— 遇到音符先把 `pos <= note.start` 的变速点输出（空隙用休止补齐）；音符**内部**若有变速点，按变速点切成多段，用延音 `&` 连起来，`t` 写在段间。
- **谁抓到**：`verify.py` 的"变速位置同步"检查（所有文件 `t` 序列必须与全局变速表逐点一致）。
- **通用教训**：**"事件必须落在精确时间点"的输出器，要把事件当一等公民**——让事件去切分内容，而不是等内容腾出边界。

## 7. `_action.txt` 动作抖动（M0/M4 高频切换）

- **症状**：钢琴演奏时音符间极短的休止被判"无音乐"，`M0`↔`M4` 每拍切换几十次，人物动作狂抖。
- **修法**：合并活动区间时加 `min_rest`（默认 1 拍）——间隙小于该值视为连续演奏，不切 M0。参数 `--action-min-rest`。
- **谁抓到**：人眼看 `_action.txt` 输出（本项目唯一靠目测抓到的 bug，因为"技术上正确、体验上错误"）。
- **通用教训**：**校验通过 ≠ 体验正确**。凡生成给人/游戏角色消费的指令流，要专门检查一次"切换频率"。

## 8. Python 测试脚本命名遮蔽标准库

- **症状**：`import dataclasses` 报 `SyntaxError: unexpected character after line continuation`（误导性极强）。
- **根因**：测试文件命名 `tests/inspect.py`，脚本目录在 `sys.path[0]`，遮蔽标准库 `inspect`，而 `dataclasses` 依赖 `inspect`。
- **修法**：改名 `inspect_midi.py`。
- **通用教训**：**`tests/` 下的脚本不要用标准库/三方库同名**（`inspect`、`types`、`email`、`token`、`string`、`plistlib`…）。

## 9. 接线错误：新参数没传进去

- **症状**：`TypeError: voice_to_mml() got an unexpected keyword argument 'max_dots'`。
- **根因**：给函数加了参数，但调用点没同步。
- **修法**：签名与调用点一起改；改完立刻 `ast.parse` + 跑一遍冒烟转换。
- **通用教训**：**加参数 = 改三处**（签名、内部使用、调用点）。
